# 新增一个机器人项目

本仓库是 monorepo：`projects/` 放"某个机器人的完整工程"，`packages/` 放"谁都能用的库"。
这份文档说明**新项目该怎么放**，以及**什么情况下不该放进来**。

## 一、先判断放在哪

| 你想加的东西 | 放哪 | 判断标准 |
| --- | --- | --- |
| 一个机器人的仿真 / 导航 / 抓取工程 | `projects/<project-name>/` | 它是**可独立运行**的完整工程，有自己的环境与构建方式 |
| 多个项目都会用到的算法或工具 | `packages/<package-name>/` | 它**与具体机器人无关**，换一个机器人依然成立 |
| 一个机器人专属、但多个子包共用的工具 | 该项目目录内部 | 只要别的 project 用不上，就不要上升到 `packages/` |
| 与仓库主题无关的东西 | 别处 | 见下文"不该放进来" |

> 铁律：**`projects/` 之间不允许互相依赖。** 需要共用就下沉到 `packages/`。

## 二、目录规范

```
projects/<project-name>/
├── README.md          # 必需：项目入口文档（模板见下）
├── ros2_ws/           # ROS 2 项目：项目自己的工作空间
│   └── src/<pkg>/     #   包名用 snake_case，目录名用 kebab-case
├── docs/              # 可选：项目专属长文档、图片、录屏
├── assets/            # 可选：演示 GIF、架构图（不要放几十 MB 的原始录屏）
└── ...
```

命名：

- 项目目录：`kebab-case`，例如 `tianyi25-sim`、`ur5-arm-pick`
- ROS 2 包：`snake_case`，例如 `tianyi25_sim`
- Python 包：`snake_case`，并且**目录名必须与 import 名一致**（历史教训：目录叫
  `algorithm_template_model`、包叫 `reusable_model`，直接导致全部测试挂掉）

## 四、接入自检清单

提 PR 前逐条确认：

- [ ] **能在干净环境跑起来**：从 `git clone` 开始，README 里的命令可以复制粘贴一路到底
- [ ] **有验证方法**：明确写出"怎么知道它是好的"，而不是只说"启动成功"
- [ ] **无绝对路径**：不出现 `/home/<某人>/...`；路径一律相对或来自包内 `get_package_share_directory`
- [ ] **无私有资产**：不含公司内部数据、密钥、`.env`、未授权的第三方模型/网格
- [ ] **无构建产物**：没提交 `build/`、`install/`、`log/`、`__pycache__/`
- [ ] **有许可证**：新增第三方资源须说明来源与许可，且与 Apache-2.0 兼容
- [ ] **更新了根索引**：根 `README.md` 的「项目索引」表加了一行
- [ ] **更新了 `CHANGELOG.md`**
- [ ] **公共部分已下沉**：重复代码抽到 `packages/`，而不是复制两份
- [ ] **CI 通过**：`.github/workflows/` 里的检查全绿

## 五、不该放进来

- 与机器人开发无关的代码、课程作业、临时试验
- 只有一次大提交、无法复现的"代码倾倒"
- 体积巨大的二进制资源（原始点云、录屏、数据集）——请用 Release 附件或外部存储，并在 README 里给出获取方式
- 有许可证冲突的代码：本仓库是 Apache-2.0，GPL 代码不能直接并入

## 六、这个项目该不该独立成仓库

留在 monorepo 的信号：

- 还在快速演进，接口频繁变动
- 与仓库内其他项目共享概念、术语、约定
- 维护者就是仓库维护者本人

考虑拆出去独立仓库的信号：

- 有独立的外部使用者，需要自己的 issue 追踪与发布节奏
- 需要独立的 CI 时间或平台（例如只能在特定硬件上构建）
- 体积或依赖已经明显拖慢整个仓库的克隆与 CI

即使拆出去，也建议在本仓库 `README.md` 的项目索引里保留一行链接，形成入口聚合。
