## 4. 自建 Action

| A3 | `/greeting/play_motion` | `greeting_interfaces/action/PlayMotion` | **A** | orchestrator | A |

## 5. 接口定义全文（冻结）

### 5.1 消息

`greeting_interfaces/msg/ConsoleCommand.msg`

```text
std_msgs/Header header
string cmd               # start | pause | resume | next | prev | goto | stop | manual
string arg               # goto 的段号等参数
string operator_id       # 操作人标识（追溯用）
```

`greeting_interfaces/msg/GreetingEvent.msg`

```text
std_msgs/Header header
uint8 EVENT_LEADER_ARRIVED = 1   # 辅助：领导就位提示（不自动接待）
uint8 EVENT_LEADER_LEAVE   = 2
uint8 EVENT_MANUAL_START   = 3
uint8 EVENT_END            = 4
uint8 event_type
float32 distance_m
string source            # perception | console | panel
```

`greeting_interfaces/msg/PersonDetection.msg`

```text
std_msgs/Header header
bool detected
float32 distance_m
float32 bearing_rad
int32 count
float32 confidence
```

`greeting_interfaces/msg/GreetingIntent.msg`

```text
std_msgs/Header header
string raw_text
string intent            # ask_topic | greeting | farewell | unknown
string slot_json         # 例: {"topic":"innovation_chain"}
float32 confidence
```

`greeting_interfaces/msg/SubsystemHealth.msg`

```text
std_msgs/Header header
bool robot_control_alive
bool arm_cmd_has_subscriber
bool chassis_rest_ok
bool audio_ok
bool script_version_ok
uint8 slam_status        # 0 正常 / 1 丢失 / 2 精度下降 / 3 异常 / 4 空闲 /
                         # 5 等待重定位 / 6 重定位中 / 7 加载地图 / 8 等待传感器
uint8 dtc_level          # 0 OK / 1 INFO / 2 WARNING / 3 ERROR / 4 FATAL
string detail
```

> `slam_status` 取值语义与底盘 `GET /api/core/slam/v1/localization/status` 的 `slam_status` 一一对应（v1.1 补齐 4/7/8）。

### 5.2 服务

`greeting_interfaces/srv/GreetingControl.srv`

```text
string cmd               # start | pause | resume | stop | next | prev | goto | manual
string arg
string operator_id
---
bool success
string message
string current_state     # 返回当前状态与讲稿段号
```

### 5.3 Action

`greeting_interfaces/action/Speak.action`

```text
# goal
string text
bool interrupt           # true = 打断当前播报
float32 resume_point     # 续播起始位置（0.0~1.0）
---
# result
bool success
string message
---
# feedback
float32 progress         # 0.0 ~ 1.0
string speaking_text
```

`greeting_interfaces/action/NavigateTo.action`

```text
# goal
string waypoint          # 点位名，查 config/waypoints.yaml
float32 timeout_s
---
# result
bool success
string message
---
# feedback
string phase             # navigating | arrived | retrying | relocalizing
float32 distance_remaining_m
```

> 🔴 `waypoint` 合法取值 = `greeting_nav/config/waypoints.yaml` 的 `waypoints` 键集合。**规范点位集（冻结）**：`standby`（迎宾位，基准）/ `explain_point`（讲解位，展板/大屏前）/ `photo_point`（合影位，可选），与规划方案 §7.6、§8 一致。**任何讲稿引用的点位名必须先在点位表定义**，否则 goal 被 `REJECT`。
> ✅ v1.1 已解决：`greeting_script.yaml` 由旧名改为规范名（`desk→explain_point`、`pillar_a→photo_point`，`standby` 不变）；`greeting_nav/config/waypoints.yaml` 同步补 `explain_point`/`photo_point` 两键（坐标沿用 `desk`/`pillar_a`）。

`greeting_interfaces/action/PlayMotion.action`

```text
# goal
string motion_name       # salute_bow | wave_official | point_right | point_left
                         # | farewell_bow | photo_pose | idle_scan
float32 speed_scale      # ★礼仪动作统一 ≤0.7，避免机械感与幅度过大
---
# result
bool success
string message
---
# feedback
float32 progress
```

> 🔴 v1.2 起**移除**动作名 `dance`（迎宾舞）：合法动作名以 `greeting_body/config/motions.yaml` 为准；服务端对未知 `motion_name` 一律 `REJECT`。

## 6. 字段语义（单位 / 范围 / 枚举）冻结说明

| 字段 | 单位 | 范围 | 说明 |
| --- | --- | --- | --- |
| `ConsoleCommand.cmd` | — | 枚举 | `start`/`pause`/`resume`/`next`/`prev`/`goto`/`stop`/`manual`；🔴 新增枚举必须走接口变更流程 |
| `ConsoleCommand.arg` | — | — | 仅 `goto` 用（段号字符串，从 1 计）；其余为空串 |
| `PersonDetection.distance_m` | m | ≥ 0 | `detected=false` 时字段无效（置 0） |
| `PersonDetection.bearing_rad` | rad | ±π | 相对机体正前方，逆时针为正 |
| `PersonDetection.confidence` | — | 0.0~1.0 | 🔴 仅本字段用于阈值判断；下游不得反推距离 |
| `GreetingIntent.slot_json` | — | JSON 字符串 | 🔴 不允许生成文案，只填槽位 |
| `SubsystemHealth.slam_status` | — | 枚举 | 0/1/2/3/4/5/6/7/8（取自底盘 `slam_status` 语义，见 §5.1） |
| `SubsystemHealth.dtc_level` | — | 枚举 | 0 OK / 1 INFO / 2 WARNING / 3 ERROR / 4 FATAL；🔴 ≥3 触发降级 |
| `NavigateTo.timeout_s` | s | > 0 | ≤0 时服务端回退 `default_timeout_s`；超时返回失败，由编排层决定重试或原地接待 |
| `NavigateTo.distance_remaining_m` | m | ≥ 0 或 `NaN` | `retrying`/`relocalizing` 阶段无距离，置 `NaN` |
| `PlayMotion.speed_scale` | — | ≤ 0.7 | 🔴 礼仪硬要求，编排层与服务端**各钳一次**（服务端下限 0.05） |
| `Speak.resume_point` | — | 0.0~1.0 | `0.0` 表示从头，`>0` 表示从比例位置续播 |
| 本体关节 `MotorCtrl.pos` | rad | 见 §7.1 关节表 | 下发前按 URDF `<limit>` 收缩 0.05 rad 后钳制；单帧增量 ≤0.2 rad |
| 所有 `Header.frame_id` | — | — | 自建话题统一填 `""`；🔴 本体控制帧必须填 `head`/`arm`/`waist`（见 §7.1）；不填垃圾值 |

## 7. 外部接口依赖（🔴 原样使用，禁止重命名 / 禁止再包一层）

### 7.1 本体（ROS2 框架，设备网 `192.168.41.2`）

消息包：**`ros2_bridge_msgs`**（来源 `xos/ros2_bridge_msgs`）。

| 用途 | 接口 | 类型 / 消息 | 使用方 | 关键约束 |
| --- | --- | --- | --- | --- |
| 头部动作 | `/head/cmd` | `ros2_bridge_msgs/msg/HeadCtrl` | A | 3 电机 ID 1/2/3（roll/pitch/yaw） |
| 手臂动作 | `/arm/cmd` | `ros2_bridge_msgs/msg/ArmCtrl` | A | 左 11–17 / 右 21–27；🔴 左右共 14 电机合并为**一条**消息、整组下发 |
| 腰部动作 | `/waist/cmd` | `ros2_bridge_msgs/msg/WaistCtrl` | A | 31=waist_yaw、32=waist_pitch |
| 腿部动作 | `/leg/cmd` | `ros2_bridge_msgs/msg/LegCtrl` | 🔴 **禁止使用** | 有倾倒风险，接待场景禁用 |
| 关节状态 | `/robot_state` | `ros2_bridge_msgs/msg/RobotState` | A / P | ✅ v1.1 确认类型；结构 `head/waist/arm/leg` 各组 `status[]`（`MotorStatus`），字段 `name=电机ID, pos(rad), speed, current, temperature, mos_temperature, error`；🔴 `error=0` 且 `pos` 在硬限位内才算有效（掉线时 `pos` 恒为 0.0 的假值） |
| TTS 播报 | `/intelligent_interaction/tts/play` | `interaction_msgs/srv/TtsService` | B | `{cmd:'append', type:'text', text:'…'}`；⚠️ 平台文档 §4.3 另列 `/audio_play/play_text` 等，两组是否同一链路待 B 实机确认 |
| 交互开关 | `/intelligent_interaction/interactive/state` | `interaction_msgs/srv/InstructionService` | B | `{cmd:'start'/'stop'}`，仅问答环节 |
| 头部相机 | `/ob_camera_head/color/image_raw`、`/depth/image_raw`（跨机用 `/compressed`、`/compressedDepth`） | `sensor_msgs/msg/Image` | C | 30Hz，`best_effort` |
| 相机开关 | `/ob_camera_head/set_streams_enable` | `std_srvs/srv/SetBool` | C | 合规开关，一键关闭 |

**🔴 控制帧构造约定（v1.1 新增，`greeting_body/body_adapter.py` 实测一致）**

| 项 | 约定值 | 说明 |
| --- | --- | --- |
| 消息结构 | `HeadCtrl/ArmCtrl/WaistCtrl` → `header` + `mode` + `label` + `reserved` + `ctrl[]`（`MotorCtrl`） | `MotorCtrl` 字段：`name(uint16 电机ID)`、`kp`、`kd`、`pos`、`spd`、`tor`、`cur`、`joint_ids` |
| `mode` | **0 = 位置模式** | 天轶 2.5 官方实现（`body_control`）一律用位置模式；`kp=kd=tor=0`，**SDK 不传增益**，刚度由驱动器内部决定。🔴 不默认使用 `mode=1` 力位混合（本机型实测持续高频啸叫） |
| `label` | `0` | 调用标签 |
| `reserved` | **`165`** | 🔴 SDK 模式移交魔数：首次下发才触发「整机 → SDK」控制权移交 |
| `header.frame_id` | `head` / `arm` / `waist` | 与话题对应 |
| `ctrl` 组帧 | 每组**必须整组**（臂 14 个全给），缺失则该组本帧跳过 | 顺序即 `ctrl[]` 顺序，不可调换 |
| `spd`（位置模式） | 「期望速度」，逐关节按行程分配，`≥ 轨迹实际速度` | 否则电机持续滞后追赶 → rush-and-wait 抖动；前馈速度上限 `3.0 rad/s` |
| 下发频率 | **≥10 Hz 连续保持**；`greeting_body` 默认 **50 Hz** | 命令非一次性生效（v1.0「`--times 20 -r 10`」仅够验证，实机动作改用流式保持） |
| 单帧增量 | ≤ **0.2 rad** | `max_step_rad` |
| 软限位 | URDF `<limit>` 收缩 **0.05 rad** | `soft_limit_margin_rad` |
| 臂跟随误差钳制 | ≤ **0.10 rad** | 防止 Kp 顶死限位造成粘滑颤振 |

**关节表与电机 ID（来源 `greeting_body/config/joint_map.yaml`，已与 URDF `<limit>` 及实机 `config_ty2.5.yaml` 逐项核对）**

| 部位 | 电机 ID | 关节（URDF 名） | 行程 lower~upper (rad) |
| --- | --- | --- | --- |
| 头 | 1 / 2 / 3 | `head_roll` / `head_pitch` / `head_yaw` | ±0.4538 / ±0.4363 / ±1.5708 |
| 腰 | 31 / 32 | `waist_yaw` / `waist_pitch` | ±3.1416 / 0.0~2.1817 |
| 左臂 | 11–17 | 肩pitch/肩roll/肩yaw/肘pitch/肘yaw/腕pitch/腕roll | 见下注 |
| 右臂 | 21–27 | 同左臂同序 | 见下注 |
| 腿 | 51 / 52 | — | 🔴 **禁止下发**，`joint_map.yaml` 不含腿 |

> 左/右臂行程：`shoulder_pitch ±2.9671`；`shoulder_roll` 左 `-0.2094~2.6180`、右 `-2.6180~0.2094`；`shoulder_yaw ±2.9671`；`elbow_pitch -2.6180~0.2618`；`elbow_yaw ±2.7925`；`wrist_pitch -0.7854~1.0472`；`wrist_roll ±1.6057`。
> ⚠️ v1.0 曾写腰部 `32 ±1.35`、头部 `±0.4/±0.4/±1.5`：v1.1 以 `joint_map.yaml`（URDF+实机核对值）为准。头部数值差异为「硬限位 vs 收缩 0.05 后软限位」，腰 pitch 实为**单向前倾** `0.0~2.1817`（v1.0 的 ±1.35 有误）。

**🔴 发布前置条件（缺一即静默失败 / 危险）**

1. 通道预检：`ros2 topic info <topic>` 确认 `Subscription count ≥ 1`，否则命令被静默丢弃且无报错（`body_adapter.check_channels`）。
2. 电机健康预检：`/robot_state` 中待用电机须「有反馈、`error=0`、`pos` 在硬限位 ±0.2 rad 内」（`body_adapter.motor_health`）。🔴 通道在线 ≠ 电机在线，掉线时 `pos` 恒为 0.0 假值，会污染起点基线导致首帧跳变。

### 7.2 底盘（晓悟 XC-MIN-V1，HTTP REST）

- 地址：`192.168.11.10:9090`（默认 host/port，见 `greeting_nav/chassis_client.py`）
- 🔴 **运动接口是 fire-and-forget**：下发返回 `action_id` 后**必须自行轮询**位姿判定到达。
- 🔴 能力缺口（不可假设）：**无软件急停**、**无导航暂停/恢复**、**无 `cmd_vel` 流式速度**、**无服务端任务队列**。安全只依赖**物理急停 + 人员值守**。

| 用途 | 方法 + 路径 | 使用方 |
| --- | --- | --- |
| 底盘健康（pre-flight） | `GET /api/core/system/v1/robot/health` | A |
| 位姿（到点主判据） | `GET /api/core/navigation/v1/pose`（x/y/yaw/confidence/status） | A |
| 定位状态 | `GET /api/core/slam/v1/localization/status`（slam_status） | A |
| 重定位 | `PUT /api/core/slam/v1/localization/recover`（建议 `alg_relocalize`） | A |
| 导航到点 | `PUT /api/core/navigation/v1/actions/moveto`（map 帧，直线 ≤10m） | A |
| 相对移动 | `PUT /api/core/navigation/v1/actions/moveby`（odom 帧，不依赖 SLAM） | A（脱困） |
| 动作状态轮询 | `GET /api/core/motion/v1/actions/{action_id}` | A（仅提前发现显式失败，字段未固化，**不作到点主判据**） |
| 取消动作 | `PUT /api/core/navigation/v1/cancel_action`（空列表=取消全部） | A（暂停 = 取消 + 重发） |
| 全局限速 | `PUT /api/core/system/v1/parameter`（`max_moving_speed` / `max_angular_speed`） | A |

🔴 安全：固件硬上限线速度 `≤1.5 m/s`、角速度 `≤1.5708 rad/s`；**本项目应用层软限速** `0.4 m/s` / `0.5 rad/s`（`navigate_to` 默认，需 `apply_speed_limit:=true` 生效）；**原地优先**。

> 到点判定（契约要求，非 SDK 返回）：位置 ≤10 cm、角度 ≤2°，且静止确认（窗口 0.5 s 内位置变化 ≤2 cm、角度 ≤0.5°）。
> 失败处理：超时/失败 → 重试 1 次 → `recover_localization` → 交由编排层**原地接待** + 告警。

## 9. 坐标系与 TF 约定（冻结）

| 坐标系 | 发布者 | 用途 |
| --- | --- | --- |
| `map` | 底盘 | 全局定位基准；`moveto` 使用 map 帧 |
| `odom` | 底盘 | `moveby` 使用 odom 帧 |
| `base_link` | 底盘 | 底盘基座 |
| 本体关节坐标系 | 本体 URDF / `robot_state_publisher` | 头、臂、腰（人形本体侧） |

🔴 **重要约束**：本体与底盘是两套独立系统，TF 树大概率不连通；本体**无 IK**，因此**不做任何跨系统坐标换算**——底盘负责"在哪里"（map 帧），本体只负责"做什么姿态"（关节空间）。
🔴 任何人不得新增跨系统 TF 转换节点或假设两棵树连通；点位一律以 `moveto` + 现场实测标定为准。
> 平台文档 §4.7 给出的是**典型** TF 链（`map → odom → base_link → waist → …`），仅作调试参考；本项目**不依赖**其连通性。
