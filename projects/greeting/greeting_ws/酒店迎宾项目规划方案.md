## 0. 一分钟摘要

| 项 | 内容 |
| --- | --- |
| **做什么** | 让天轶 2.5（人形本体 + 晓悟具身底盘）在**固定接待区域**内，按仪式化脚本完成**迎接领导 （礼貌性问候）→ 主题讲解（"三谷十链群"）→ 交流问答**的接待任务 |
| **场景定性** | **计划性、仪式化、有主持人的政务/商务接待**，不是随机客流的自动迎宾；一次接待的成功率与"口径准确性"比"自主性"更重要 |
| **核心卖点** | ① 领导到达即按脚本致意（端庄礼仪）；② "三谷十链群"主题讲解口径 100% 与客户文案一致；③ 操作手可随时一键接管，全程可控 |
| **技术栈** | 本体：Jetson + **ROS2 Jazzy**（`source ~/xos/setup.bash`）｜ 底盘：晓悟 XC-MIN-V1 + **HTTP REST 9090**（固定范围内短距移动）｜ 编排：Python 显式状态机 |
| **主要难点** | ① 本体**无 IK / 无笛卡尔 / 无 MoveIt**，礼仪动作只能示教+关节插值；② **`robot_control` 会静默退出**（一次接待失败即现场事故）；③ 底盘 REST **无软件急停 / 无暂停恢复**；④ **ASR / 唤醒 / TTS 停止接口均不存在**；⑤ 领导在场，**安全与可控性等级最高** |
| **最大不确定项** | **固定范围的边界定义**（原地 / 几点位 / 多大面积）、**触发方式**（触发 / 自动感知）、**"三谷十链群"权威讲解口径的交付**、算力板型号与显存、固件中未交付的 ROS2 消息包 |
| **建议人力** | 4~5 人核心团队（PM/系统 1、机器人软件 2、内容/算法 1、测试/实施 1）——较 v1.0 精简，因视觉自研与全域导航不再是刚需 |
| **工期口径** | 按 **阶段 + 退出准则（Exit Criteria）** 组织，不预设绝对工期；实际排期由资源投入与现场条件确定 |

> 本方案的接口立论基础：本体与底盘能力清单已在《智能导览项目规划方案》中通过逐字穷举原始文档 + 实机取证完成。本方案**复用该清单**，并按"固定范围领导接待"场景重新裁剪编排层与能力层范围。

## 1. 项目背景与目标

### 1.1 背景

围绕"三谷十链群"搭建产业链、创新链双向高效互通桥梁，促进优势产业、优势学科多维联动投资合作，推动现代产业体系创新发展，需在接待场所设置**智能迎宾机器人**，承担来访领导的迎接、主题讲解与陪同引导工作。

采用天轶 2.5 人形机器人，其具备人形外观、头部、双臂、语音外设与板载算力，配合晓悟具身底盘，可在**不依赖云端**的前提下完成"迎接—讲解—交流"的接待闭环，同时体现校地合作的科技形象。

### 1.2 建设目标

**总目标**：机器人在**固定接待区域内**，按客户确认的脚本完成领导接待迎宾全流程，讲解口径与客户文案完全一致，全程可被工作人员接管。

拆解为 5 条可验证目标（KPI，指标为建议值，需与客户确认）：

| # | 目标 | 量化指标（建议） |
| --- | --- | --- |
| G1 | 接待流程完整性 | 按脚本完成率 ≥ 98%（重点场次**一次成功**）；关键环节无遗漏 |
| G2 | 讲解口径准确性 | 与客户提供文案一致率 **100%**（禁止自造内容）；无臆测数据 |
| G3 | 礼仪表现 | 致意动作到位率 ≥ 98%；动作幅度符合礼仪规范；无夸张/机械感过强的动作 |
| G4 | 可控性 | 主持人一键暂停/接管响应 ≤ 200ms；任意时刻可安全停机；无"静默无响应" |
| G5 | 安全性 | 零碰撞、零夹伤；急停响应 ≤ 200ms；领导在场时全程有工作人员持物理急停 |

> **目标优先级**：`G2 口径准确性` 与 `G4 可控性` > `G1 流程完整性` > 其他。领导接待场景中，**一次讲错内容或一次失控，代价远高于"不够智能"**。

### 1.3 范围界定

**做（In Scope，一期）**

- 接待状态机（待机 → 迎宾致意 → 主题讲解 → 交流问答→ 复位）
- **操作手控制台**（一键启动/暂停/接管/复位/切换讲稿）—— 本期必备，非可选
- 迎宾与讲解动作库（致意、鞠躬、指引、待机巡视）—— 示教录制 + 关节插值 + 流式下发
- 语音链路：**TTS 复用本体服务** + 操作手触发话术；ASR 作为"交流问答"环节的可选能力
- 固定范围内短距移动（迎宾位 ↔ 讲解位 ↔ 合影位，单段 ≤ 10m）
- 主题知识库与讲稿管理（"三谷十链群"、产业链创新链互通、优势产业/学科联动、投资合作）
- 健康守护与故障自愈（`robot_control` / 话题订阅者 / REST 连通性）
- 现场建图、点位标定、礼仪调参、验收

**不做（Out of Scope，一期）**
- 全域自由行走引导（本期限定固定范围；跨楼层/电梯引导明确不做）
- 人脸识别 / 领导身份识别 / 影像留存（**合规红线**，见 §13 Q7）
- 机械臂抓取/递物（除非客户明确要求）
- 自主探索式建图（厂商明确不支持）
- 多机调度、云端集群管理、小程序/APP 端
- 自动回充（官方无自动回充文档，纳入运营 SOP）

## 2. 需求解析：接待场景与流程

### 2.1 场景定性（决定架构的三条判断）

| # | 判断 | 依据 | 架构后果 |
| --- | --- | --- | --- |
| J1 | 接待是**计划性**的，不是随机客流 | 领导来访有行程安排、有主持人/讲解员 | 触发以**人工为主**，视觉自动感知降为辅助 |
| J2 | 接待是**仪式化、一次成功**的 | 重点场次无重来机会 | 必须有演练模式、脚本可预演、进度可视；不能依赖"自动重试" |
| J3 | **固定范围**内活动 | 客户明确"在固定范围迎宾" | 导航模块大幅简化；优先原地动作，移动仅在明确指令下执行 |

### 2.2 接待业务流程（仪式化脚本）

| 步 | 阶段 | 机器人行为 | 系统能力要求 |
| --- | --- | --- | --- |
| 1 | **待机驻位** | 停在迎宾位，头部慢速巡视，姿态端庄 | 待机姿态预设、事件监听、主持人链路在线 |
| 2 | **领导到达** | 主持人触发（或辅助感知提示）→ 机器人启动 | 人工触发为主通道；`/greeting/panel_command` |
| 3 | **迎宾致意** | 抬头注视 + 端庄致意（鞠躬/挥手，幅度收敛）+ 欢迎语 | 礼仪动作序列、TTS 播报、动作与语音同步 |
| 4 | **引导移位** | （可选）引导至讲解位 / 合影位，单段 ≤ 10m | 固定范围内 `moveto`（map 帧 ≤10m）或原地不动 |
| 5 | **主题讲解** | 按脚本分段讲解"三谷十链群"合作主题，配合指引手势 | **讲稿分段管理**、TTS 分段播报、动作同步、可被主持人切换/暂停 |
| 6 | **交流问答** | （可选）就产业链/创新链/学科联动等主题做受限问答 | 主题 RAG（仅答客户文案范围）+ 输出护栏；ASR 自研 |
| 7 | **送别** | 鞠躬 + 送别话术，可配合合影姿态 | 送别动作、正式话术 |
| 8 | **复位待机** | 返回迎宾位（若已移位），恢复端庄待机 | 回位导航或原地复位、状态清理 |

**关键设计洞察**：整个流程必须**可被主持人随时接管**。领导接待中，主持人可能临时增减环节、跳过讲解、延长某段停留——因此状态机必须支持"**单步推进 / 单步回退 / 跳转至任意环节**"，而不是自动一路跑完。

### 2.3 触发方式矩阵（人工为主）

| 触发方式 | 接口/实现 | 角色 | 备注 |
| --- | --- | --- | --- |
| **操作手按钮** | `/greeting/panel_command`（`std_msgs/String`） | ✅ **主通道** | 每个环节可单步触发；操作手是唯一决策者 |
| 操作手控制台 | `/greeting/control` 服务 | ✅ **主通道** | `start / pause / resume / next / prev / goto / stop` |
| 遥控/串口按键 | 硬件按键 → `/greeting/panel_command` | 备用 | 演示与应急用 |
| 语音指令（工作人员） | 自研唤醒 + 指令词 | 备用 | 仅在安静场合可用 |
| **视觉自动感知** | 自研检测，订阅 `/ob_camera_head/color/image_raw` | ⚪ **辅助** | 仅用于"领导已就位"提示与安全避障辅助，**不直接驱动接待流程** |

> 🔴 **架构决定**：v1.0 把视觉自动迎宾作为主通道；本场景下**降为辅助**。好处：消除"误触发接待到无关人员"的礼仪风险，同时**自研人检测从刚需降为可选项**（降低风险等级，见 §11 R4）。

### 2.4 主题内容要求（口径红线）

讲解内容围绕以下主题，**文案必须由客户提供权威口径**：

| 主题 | 说明 | 我方职责 |
| --- | --- | --- |
| "三谷十链群" | 客户既定产业规划主题 | **照稿播报**，不做任何解释性改写或补充 |
| 产业链、创新链双向高效互通 | 合作机制表述 | 同上 |
| 优势产业、优势学科多维联动投资合作 | 合作内容表述 | 同上 |
| 现代产业体系创新发展 | 合作目标表述 | 同上 |

> 🔴 **强制约定**：
> ① 所有涉及产业规划、政策表述、数据指标的文案，**必须逐字使用客户提供的版本**，机器人不得生成、改写或推断；
> ② 知识库中**只允许存在客户审核通过的文本**；
> ③ 交流问答环节对超出知识库范围的问题，统一走**礼貌拒答 + 引导至工作人员**，禁止模型自由发挥；
> ④ 讲稿版本需可追溯（版本号 + 审核人 + 生效日期），变更需重新审核。

### 3.2 软件分层架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ L5 应用层   greeting_orchestrator  接待状态机（唯一指挥者）               │
│             · 仪式化脚本 · 单步推进/回退/跳转 · 可随时接管                 │
│             · greeting_console 主持人控制台（本期必备）                  │
├──────────────────────────────────────────────────────────────────────┤
│ L4 智能层   greeting_dialog   主题问答（受限于客户文案）+ 输出护栏          │
├──────────────────────────────────────────────────────────────────────┤
│ L3 能力层   greeting_body(礼仪动作库)  greeting_voice(TTS/ASR)          │
│             greeting_nav(固定范围短距移动)  greeting_perception(辅助)    │
│             greeting_health(守护与自愈)                                │
├──────────────────────────────────────────────────────────────────────┤
│ L2 接口层   ROS2 Topic/Service/Action（本体） ｜ HTTP REST 9090（底盘）  │
├──────────────────────────────────────────────────────────────────────┤
│ L1 运行环境 ROS2 Jazzy · DDS(FastDDS,锁版本) · CUDA/TensorRT · 网络/安全 │
└──────────────────────────────────────────────────────────────────────┘
```

**架构原则**：
1. **主持人拥有最高权限**——`greeting_console` 的控制指令优先级高于一切自动逻辑；
2. **全系统只有一套状态机**（`orchestrator`），本体与底盘均为被调用能力；
3. **原地动作优先**——能在迎宾位完成的不移动；移动必须由明确指令触发。

### 3.3 关键接口现状（已实测 / 文档确认）

**本体关节控制接口（只有关节空间、流式发布）**

| 能力 | 接口 | 类型 | 备注 |
| --- | --- | --- | --- |
| 关节状态 | `/diagnose/robot_state` | ROS2 Topic（**消息类型未确认**） | `pos/speed/current/temperature/mos_temperature/error`，`error=0` 为正常 |
| 头部控制 | `/head/cmd` | `ros2_bridge_msgs/msg/HeadCtrl` | 关节 1 歪头 / 2 抬头 / 3 转头；限位 ±0.4、±0.4、±1.5 rad |
| 手臂控制 | `/arm/cmd` | `ros2_bridge_msgs/msg/ArmCtrl` | 左臂 11–17 / 右臂 21–27；**单次位置差 ≤ 1.9 rad** |
| 腰部控制 | `/waist/cmd` | `ros2_bridge_msgs/msg/WaistCtrl` | 关节 31 ±3.0、32 ±1.35 rad |
| 腿部控制 | `/leg/cmd` | `ros2_bridge_msgs/msg/LegCtrl` | 关节 51 −3.0~0、52 0~1.1 rad（**有倾倒风险，接待场景禁止使用**） |

**通用消息字段**：`header{stamp,frame_id}` + `mode` + `label`(语义未确认) + `ctrl[]{name,pos,spd,cur}`；
`mode`：0 位置 / 1 力位混合 / 2 速度 / 3 标零 / 4 距离 / 5 电流。

> 🔴 **发布约定（关键约束）**：控制命令**不是一次性生效**，需 `--times 20 -r 10`（约 2 秒 @10Hz）连续下发保持。这是动作库实现的核心约束。
> 🔴 **发布前置条件**：下发前必须 `ros2 topic info /arm/cmd` 确认 `Subscription count ≥ 1`，否则命令无效且无任何报错。

**语音与交互**

| 能力 | 接口 | 类型 | 备注 |
| --- | --- | --- | --- |
| TTS 播报 | `/intelligent_interaction/tts/play` | `interaction_msgs/srv/TtsService` | `{cmd:'append', type:'text', text:'…'}` |
| 语音交互开关 | `/intelligent_interaction/interactive/state` | `interaction_msgs/srv/InstructionService` | `{cmd:'start' / 'stop'}` |
| 音频底层 | `aplay -D default <wav>` / `thor_audio_init.sh` / `amixer -c 1 sset Speaker 100%` | Shell | 音量与音频链路排障 |

> ⚠️ **ASR 独立接口、唤醒词接口、TTS 停止/打断接口均未找到**；宣传页所述"内置 LLM 小模型 + RAG + 多轮对话"**没有任何对应 API 名称**。
> 本场景下：**TTS 是刚需（讲解必须播报）**；ASR 是"交流问答"环节的可选能力，若不可靠可直接由主持人代答，不影响主流程。

> 从固件镜像提取到（**存在但未交付，等于没有**）：
> - 话题：`/alg_knewbots/nav_status`(1Hz)、`/alg_knewbots/pose`(50Hz)、`/knewbots/robot_basic_state`(5Hz)、`/<subsystem>/status`(DTC，9 个子系统)
> - 服务：`/alg_knewbots/{start_mapping,stop_mapping,start_localization,alg_relocalize}`、`/knewbots_map_server/load_map`、`/task_manager/query/*`
> - Action：`/task_manager/submit_task`、`/move_to`、`/move_to_locations`、`/move_by_direction`、`/go_home`、`/navigate_to_pose`
> - 消息包：`knewbots_msgs`、`task_manager_msgs`、`robotic_adapter_msgs`
>
> ⇒ **仍建议向厂商索取**（尤其 `/go_home` 用于自动回位）；但本场景固定范围、点位少，**REST 兜底方案已足够**，不再作为关键路径阻塞项。

> ⚠️ **REST/SDK 能力缺口（直接影响架构）**：
> ① **无软件急停**；② **无导航暂停/恢复**（只能 `cancel_action` 后重下发）；③ **无 `cmd_vel` 流式速度控制**；④ **无服务端多点任务队列**。
> ⇒ 领导接待场景下：**安全只能依赖物理急停 + 工作人员就近值守**；主持人"暂停"实现为 `cancel_action` + 记录现场，恢复时重新下发。

### 3.5 架构级空白与强制约定（必须写入开发规范）

**空白一：本体没有 IK / 笛卡尔 / Action 接口**
全文穷举 `ik`、`逆解`、`笛卡尔`、`pose`、`action`、`moveit`、`轨迹` **零命中**，本体只有关节空间流式话题。礼仪动作（致意、鞠躬、指引）**不能**用"给我朝向坐标 (x,y,z)"实现。
⇒ 唯一可行路线：**示教 → bag 录制关节关键帧 → 按 ≤1.9 rad 分段插值 → 流式下发 `/arm/cmd` + `/head/cmd` + `/waist/cmd`**（见 §7.5）。

**空白二：`robot_control` 会静默退出**
实测 `robot_control` 会在 3~4 分钟后以 `Stop requested` 静默退出，而 `proc_manager` 状态看起来**仍然正常**，命令发出去没有任何反应且**无任何报错**。
⇒ **强制约定**：任何动作下发前必须先 `ros2 topic info /arm/cmd` 确认 `Subscription count ≥ 1`；主控侧必须内置 `robot_control` 健康守护（见 §7.7）。**接待开始前必须完成一次全链路自检**（§7.8 SOP）。

**空白三：底盘无软件急停，且现场有领导**
⇒ **强制约定**：安全**只能依赖物理急停按钮**；接待全程**必须有工作人员手持/就近站位于急停旁**；限速 ≤ 0.3~0.5 m/s（固定范围短距，比 v1.0 更严）；**能用原地动作就不用移动**。

**空白四：语音链路不可复用**
ASR / 唤醒 / TTS 停止接口均不存在，内置 LLM 无 API。
⇒ **强制约定**：TTS 复用本体服务（讲解刚需）；ASR 为可选项，不可靠时由主持人代答；TTS 打断通过自建 Action 的 `cancel goal` 实现。

**其他实测坑位（写入开发规范）**

| # | 坑 | 规避方式 |
| --- | --- | --- |
| 1 | 手动启动 `robot_control` 未设实时优先级 → 关节断连 | 必须 `chrt -r -p 55` + `taskset` 绑核 9-13 |
| 2 | DDS（FastDDS 2.14.5）升级导致 segfault | **锁定版本，禁止升级** |
| 3 | `diagnostic_updater` 4.2.7 导致相机崩溃 | 回退 4.2.6 |
| 4 | 臂（CiH408）与腰腿（Zeroerr）驱动器不同，温/流读数为 0 | 未上电时属正常，勿误判为故障 |
| 5 | IMU 全零 | 驱动异常，需排查 |
| 6 | GPU 过流 | `nvpmodel -m 1`(120W) + 锁 900MHz，**限制端侧 AI 算力预算** |
| 7 | 充电需人工移机 + 插线，**无自动回充** | 一期不做自动回充，纳入接待 SOP（**重点场次前必须满电**） |
| 8 | 算力板型号文档自相矛盾（Thor / Orin 两说） | 必须实机 `nvpmodel -q` / `tegrastats` 确认 |

## 4. 接待任务编排设计（核心）

### 4.1 状态机定义

| 状态 | 名称 | 行为 | 调用的接口 |
| --- | --- | --- | --- |
| `S0` | 待机驻位 `STANDBY` | 停在迎宾位，端庄待机，头部慢速巡视 | 周期 pub `/head/cmd`（`idle_scan`）；1Hz pub `/greeting/health`；监听 `/greeting/control`、`/greeting/panel_command` |
| `S1` | 迎宾致意 `SALUTE` | 抬头注视 + 端庄致意（鞠躬/挥手）+ 欢迎语 | `PlayMotion(salute_bow / wave_official)` → 流式 pub `/head/cmd`+`/arm/cmd`+`/waist/cmd`；`Speak(欢迎语)` → call `/intelligent_interaction/tts/play` |
| `S2` | 引导移位 `REPOSITION` | （可选）移动至讲解位/合影位，单段 ≤10m | `NavigateTo(explain_point / photo_point)` → 底盘 REST `moveto` + 轮询 `GET actions/{id}`；全程**原地优先**，无指令不移动 |
| `S3` | 主题讲解 `PRESENT` | 按脚本分段讲解"三谷十链群"主题，配合指引手势 | `Speak(第 N 段讲稿)` + `PlayMotion(point_right/left)`；支持**单步推进/回退/跳转** |
| `S4` | 交流问答 `QNA` | （可选）受限主题问答 | call `/intelligent_interaction/interactive/state {cmd:'start'}`；自研 ASR → `greeting_dialog`（仅答客户文案范围）→ `Speak` |
| `S5` | 复位 `RESET` | 返回迎宾位（若已移位），状态清理 | `NavigateTo(standby)` 或原地复位；转 `S0` |
| `S6` | 主持人接管 `MANUAL` | 机器人停止自动推进，仅响应主持人指令 | 挂起全部自动逻辑；仅执行显式指令 |
| `S-ERR` | 异常降级 `DEGRADED` | 仅语音、不动手臂；重定位；兜底话术 | sub `/greeting/health`；call `alg_relocalize` |

### 4.2 状态转移表

> 与 v1.0 的"自动循环"不同，**本场景下主持人指令优先级最高，可覆盖任意自动转移**。

| 当前状态 | 事件 | 目标状态 | 动作 |
| --- | --- | --- | --- |
| `S0` | `panel: start` / `ctrl: start` | `S1` | 启动接待脚本，执行致意 + 欢迎语 |
| `S0` | 辅助感知：领导就位 | 保持 `S0` + 提示 | **不自动接待**，仅在控制台提示"领导已就位，可开始" |
| `S1` | `panel: next` 或致意完成且已配置自动推进 | `S2`（如需移位）否则 `S3` | 推进脚本 |
| `S2` | 到达目标点 | `S3` | 开始主题讲解 |
| `S2` | `panel: skip` | `S3` | 跳过移位，原地讲解 |
| `S3` | `panel: next` | `S3`（下一段）或 `S4`/`S5` | **逐段推进**，直到讲稿结束 |
| `S3` | `panel: prev` | `S3`（上一段） | 单步回退，重播上一段 |
| `S3` | `panel: goto(n)` | `S3`（第 n 段） | 跳转至指定讲稿段 |
| `S3` | 讲稿播完 | `S4`（若启用问答）否则 `S5` | 推进 |
| `S4` | 问答结束 / `panel: next` | `S5` | 推进至送别 |
| `S5` | 送别完成 | `S6` | 复位 |
| `S6` | 复位完成 | `S0` | 恢复待机，等待下一次接待 |
| **任意** | `ctrl: pause` | `S7` | **立即** `cancel` 当前 goal；记录现场状态 |
| `S7` | `ctrl: resume` | 原状态 | 恢复现场（播报从记录点续播） |
| **任意** | `ctrl: stop` / 物理急停 | `S0` / 全停 | 中止接待；急停场景等待人工弹出 |
| **任意** | 健康异常（`DEGRADED` 条件成立） | `S-ERR` | 停动作、播报兜底、尝试恢复 |

### 4.3 可接管设计（本场景的核心要求）

领导接待中主持人需要**随时干预**，因此：

1. **单步推进**：`next / prev / goto(n)` —— 主持人可自由控制讲解节奏，不用机器人自动跑完；
2. **即时暂停**：`pause` → 立即 `cancel` 当前 `Speak`/`NavigateTo`/`PlayMotion` goal；恢复时播报从记录点续播（不是重头开始）；
3. **播报打断**：本体 TTS **无 stop 接口**，因此 `Speak` 必须实现为 Action 并支持取消；
4. **导航无暂停**：REST 不支持暂停，策略是 `cancel_action` → 记住目标点位 → 恢复时**重新下发**；
5. **动作安全停**：动作库按帧流式下发，停止下发即停；但必须停在**安全姿位**（收臂、抬头、直立），不能停在半空中或非礼仪姿态；
6. **主持人优先**：任何 `console` 指令的优先级高于 `orchestrator` 的自动推进逻辑。

### 4.4 异常与降级矩阵

| 异常 | 检测方式 | 降级策略 |
| --- | --- | --- |
| `robot_control` 退出 | 1Hz 检查进程 + `/diagnose/robot_state` 有无数据 | 告警 + 自动拉起；拉起期间**仅语音、不动手臂**（讲解不中断，只失去手势） |
| `/arm/cmd` 无订阅者 | 下发前 `ros2 topic info` 检查 `Subscription count` | 跳过动作，纯语音讲解；控制台明确提示 |
| 底盘 REST 不可达 | `get_robot_health()` 超时 | **原地完成全部接待**（本场景固定范围，可完全退化为原地模式） |
| 定位丢失（`slam_status ∈ {1,3,5,6}`） | 每次下发前 pre-flight | `alg_relocalize` 重定位；失败则原地接待 |
| 移位到点超时 | 轮询超时 | 重试 1 次 → 重定位 → 原地讲解 + 控制台告警 + 请主持人接管 |
| 急停被按下（DTC `0x01010001`） | 解析 `/<subsystem>/status` | 全停，播报/控制台提示，等待人工弹出急停 |
| 相机无数据 | `ros2 topic hz` 为 0 | 不影响主流程（感知仅为辅助）；可重启 `orbbec_head.service` |
| TTS 无声音 | 接待前自检（试播一句） | 检查 `thor_audio_init.sh` / `amixer` 音量；**接待前自检为强制项** |
| 讲稿版本不一致 | 启动时校验版本号 | 拒绝启动接待，控制台告警（防讲错内容） |

### 5.3 动作（Action）

**设计原则：凡是"长时执行 / 需要反馈 / 需要取消"的操作，一律用 Action 而非 Service。** 本场景中播报、移位、动作都必须可被主持人即时打断。

| Action | Goal | Feedback | Result | 说明 |
| --- | --- | --- | --- | --- |
| `/greeting/speak` | `text, interrupt, resume_point` | `progress, speaking_text` | `success, message` | 封装本体 TTS，支持打断与续播 |
| `/greeting/navigate_to` | `waypoint, timeout_s` | `phase, distance_remaining_m` | `success, message` | 固定范围内短距移位 |
| `/greeting/play_motion` | `motion_name, speed_scale` | `progress` | `success, message` | 封装示教礼仪动作库 |

```
float32 speed_scale      # ★礼仪动作统一 ≤0.7，避免机械感与幅度过大
---
# result
bool success
string message
---
# feedback
float32 progress
```

### 5.5 QoS 规划

| 话题 | 可靠性 | 历史深度 | 理由 |
| --- | --- | --- | --- |
| `/greeting/control_cmd` | `reliable` | 10 | **主持人指令绝不可丢**（丢一条=现场失控） |
| `/greeting/events` | `reliable` | 10 | 事件不能丢 |
| `/greeting/health` | `reliable` | 10 | 状态快照需可靠 |
| `/greeting/state` | `reliable` + `transient_local` | 1 | 控制台接入即拿到当前状态 |
| `/greeting/perception/person` | `best_effort` | 5 | 辅助感知，丢帧无妨 |
| `/greeting/intent` | `reliable` | 10 | 意图不能丢 |
| `/ob_camera_head/color/image_raw` | `best_effort`（sensor data） | 5 | 相机原始流默认 sensor QoS |
| `/diagnose/robot_state` | `reliable` | 10 | 关节状态需完整（**消息类型待确认**） |
| `/head/cmd`、`/arm/cmd`、`/waist/cmd` | `reliable` | 1 | 控制指令按 10Hz 连续下发，无需积压 |

> ⚠️ **跨主机（算力板 ↔ 运动控制板）DDS 需实测**：若发布端与订阅端 QoS 不匹配，表现为"话题存在但收不到数据"。本项目所有订阅自建话题的节点，QoS 一律**显式声明**。

### 5.6 坐标系与 TF

| 坐标系 | 发布者 | 说明 |
| --- | --- | --- |
| `map` | 底盘 | 全局定位基准，`moveto` 使用 map 帧 |
| `odom` | 底盘 | `moveby` 使用 odom 帧 |
| `base_link` | 底盘 | 底盘基座 |
| 本体关节坐标系 | 本体 URDF / `robot_state_publisher` | 头部、手臂、腰部（**人形本体侧**） |

> 🔴 **重要约束**：**本体与底盘是两套独立系统，TF 树大概率不连通**。由于本体**无 IK**，本方案**不做任何跨系统坐标换算**——底盘负责"在哪里"（map 帧定位+移位），本体只负责"做什么姿态"（关节空间动作）。
> 固定范围场景下点位极少（迎宾位/讲解位/合影位），建议**以 `moveto` + 现场实测标定**为准，无需复杂 TF 链路。

## 7. 核心模块设计

### 7.1 `greeting_orchestrator`（接待状态机）

- **实现**：Python + 显式状态机（`transitions` 库或自研 FSM），**不用行为树**（流程确定、可读性高、便于现场改脚本）。
- **输入**：`/greeting/control_cmd`、`/greeting/panel_command`、`/greeting/events`、`/greeting/intent`、`/greeting/health`
- **输出**：`Speak` / `NavigateTo` / `PlayMotion` 三个 Action goal；`/greeting/state`
- **唯一指挥者**：其他模块不互相调用，一律经编排层。
- **可接管**：`console` 指令优先级最高；支持 `next / prev / goto(n) / pause / resume / manual`。
- **原地优先**：默认不移动；仅当脚本显式声明"需移位"且主持人确认时才调用 `NavigateTo`。
- **脚本驱动**：讲稿分段、动作绑定、是否移位全部由 `script.yaml` 描述，**现场改脚本不改代码**。
- **演练模式**：支持"干跑"（不驱动本体，只走状态与播报日志），供接待前预演。

### 7.2 `greeting_console`（主持人控制台，本期必备）

| 功能 | 说明 |
| --- | --- |
| 状态显示 | 当前状态、当前讲稿段号、进度、健康灯 |
| 单步控制 | `启动 / 下一段 / 上一段 / 跳转 / 暂停 / 恢复 / 停止 / 切手动` |
| 一键接管 | 大按钮，**响应 ≤ 200ms** |
| 内容切换 | 切换讲稿版本（需版本号校验） |
| 告警 | `robot_control` 退出、REST 不可达、音频异常、讲稿版本不符 |
| 追溯 | 记录操作人 + 时间 + 指令（接待复盘用） |

> 接待现场建议：触摸屏或平板，**放在主持人手边**；同时保留**物理按键**作为触屏失效时的兜底。

### 7.3 `greeting_perception`（辅助感知，可选）

- 定位为**辅助**：仅输出"领导已就位/已离开"提示，**不驱动接待流程**。
- 输入 `/ob_camera_head/color/image_raw`，输出 `/greeting/perception/person`。
- 实现可极简：帧差 + 人体轮廓/轻量检测模型即可，**无需人脸识别**。
- **合规**：本地处理、不留存图像；支持一键关闭相机流（`set_streams_enable {data: false}`）。
- 若客户不希望使用相机，**本包可整体裁剪，不影响主流程**。

### 7.4 `greeting_voice`（语音链路）

| 子能力 | 实现方式 | 本场景定位 |
| --- | --- | --- |
| TTS | **复用** `/intelligent_interaction/tts/play`（`cmd:'append'`） | ✅ **刚需**：讲解必须播报；长文本分段 |
| 打断/续播 | `Speak` Action 的 `cancel goal` + `resume_point` | ✅ 刚需：主持人随时可暂停/续播 |
| ASR | 自研（FunASR / sherpa-onnx）+ 专有词表 | ⚪ 可选：问答环节；不可靠则由主持人代答 |
| 唤醒 | 自研（sherpa-onnx / Porcupine） | ⚪ 可选：仅安静场合 |
| 音频基础 | `thor_audio_init.sh`、`amixer -c 1 sset Speaker 100%` | ✅ 接待前**强制自检**（试播一句） |

**专有词表**（提升识别率，需客户提供标准写法）：三谷十链群、产业链、创新链、优势学科、投资合作、现代产业体系、新乡市、河南科技学院，以及各"谷/链"具体名称。

### 7.5 `greeting_body`（礼仪动作库）

> 🔴 **前置结论**：本体**没有 IK / 笛卡尔 / Action / MoveIt 接口**，只有关节空间流式话题，因此礼仪动作必须走示教路线。

**动作生产流水线（示教法）**

```
1. 示教      手动拖拽/遥控本体摆出目标姿态（如"端庄鞠躬 15°""单手指示展板右侧"）
2. 录制      ros2 bag record 抓取 /diagnose/robot_state 的关节 pos
3. 提帧      在 bag 中标记关键帧（起始/中间/终止），导出为 motions/*.json
4. 校验      检查每关节是否在限位内（见 §3.3 行程表），单次位置差 ≤ 1.9 rad
5. 礼仪审查  ★幅度审查：鞠躬角度、挥手幅度、转头速度需符合政务礼仪（见下表）
6. 插值      相邻关键帧按 ≤ 1.9 rad 分段、线性或三次插值成 10Hz 序列
7. 预检      ros2 topic info /arm/cmd 确认 Subscription count ≥ 1
8. 下发      以 --times / -r 按 ≥10Hz 流式发布到 /arm/cmd、/head/cmd、/waist/cmd
9. 收尾      动作结束停在安全姿位（收臂、抬头、直立），不悬停半空
```

**礼仪动作清单（一期）与幅度规范**

| 动作名 | 含义 | 涉及关节 | 幅度/速度规范 |
| --- | --- | --- | --- |
| `idle_scan` | 待机巡视（头部慢速左右转） | head 1/2/3 | 转头 ≤ ±0.5 rad，角速度慢速 |
| `salute_bow` | 迎接时端庄鞠躬 | waist 31/32 + head | **鞠躬 ≤ 15°**，回正缓慢（≥1.5s） |
| `wave_official` | 正式致意挥手 | arm 21–27 + head | **幅度收敛**，手腕不过肩，速度 ≤0.7 |
| `point_right` / `point_left` | 指引展板/方向 | arm + head | 手臂不越过身体中线，肘部不外翻 |
| `photo_pose` | 合影姿态（面向镜头、双手自然） | arm + head + waist | 保持稳定，**无抖动**，可长时间保持 |
| `farewell_bow` | 送别鞠躬 | waist + head | ≤ 20°，回正后抬头目送 |

> **硬约束**：单次位置差 ≤ 1.9 rad；每帧参数范围见文档限位表；**腿部关节 51/52 禁止使用**（有倾倒风险）；急停按下时末端与关节均不可控。
> **礼仪硬要求**：所有动作 `speed_scale ≤ 0.7`；**禁止**快速、夸张、机械感强的动作；动作全程不得使机器人失去平衡（腰部动作幅度受限）。

### 7.6 `greeting_nav`（固定范围内短距移位）

**本场景大幅简化**（v1.0 的"多点巡航"不再需要）：

| 点位 | 用途 | 移动需求 |
| --- | --- | --- |
| `standby` | 迎宾位（待机/迎宾/送别） | 基准点，默认不移动 |
| `explain_point` | 讲解位（展板/大屏前） | 迎宾位 → 此处，单段 ≤10m |
| `photo_point` | 合影位 | 可选，单段 ≤10m |

**设计要点**
- **原地优先**：讲解若能在迎宾位完成，则不移动（减少风险与耗时）；
- **仍必须自建任务状态机**：`下发 action → 轮询 GET action_id → 判定到达/超时 → 记录位姿 → 推进`（REST 无服务端队列）；
- **Pre-flight 检查**：每次下发前 `get_robot_health()` + `get_pose()`，确认导航就绪、定位有效；
- **到点判定**：位置 ≤ 10cm、角度 ≤ 2° + 静止确认（厂商指标 ±1cm / ±1.0°，留裕量）；
- **失败处理**：超时 → 重试 1 次 → `alg_relocalize` → **原地接待** + 控制台告警；
- **速度策略**：客服端硬上限 1.5m/s；**本场景建议 ≤ 0.3~0.5 m/s**（比 v1.0 更严，因领导在场）；
- **固定范围边界**：应用层软限位（坐标围栏）+ 物理护栏/边界标记，**双重保障**；
- **DTC 监控**：解析 `/<subsystem>/status`（`0x01010001` = 急停被按下）。

### 7.7 `greeting_health`（健康守护与自愈，必须做）

| 层级 | 检测内容 | 处置 |
| --- | --- | --- |
| L1 进程守护 | 1Hz 检测 `robot_control` 存活 + `/diagnose/robot_state` 是否有数据 | 异常则告警 + 自动拉起（含 `chrt -r -p 55` + `taskset` 绑核 9-13） |
| L2 通道守护 | 下发前检查 `ros2 topic info /arm/cmd` 的 `Subscription count ≥ 1` | 封装进 `body_adapter`，**每次动作前强制预检**，不通过则降级为"仅语音" |
| L3 底盘守护 | `get_robot_health()` / `get_pose()` 连通性与定位状态 | 不可达则**全程原地接待** |
| L4 音频守护 | 周期性静默检测 + 接待前试播 | 异常则控制台告警；**接待前自检为强制项** |
| L5 内容守护 | 启动时校验讲稿版本号与审核状态 | 不符则**拒绝启动接待**（防讲错内容） |
| L6 安全守护 | 解析 `/greeting/health` 与 DTC 等级 | FATAL/急停 → 全停 + 提示 + 等待人工 |

> 领导接待场景下，L1/L2/L5 是"不翻车"的分水岭；**接待前必须跑完一次 §7.8 全链路自检**。

### 7.8 每次接待前标准流程（SOP，强制）

```
①  确认急停完全弹出；工作人员持急停就位于机器人旁
②  source ~/xos/setup.bash
③  systemctl status proc_manager            # 正常不代表 robot_control 在跑
④  ps aux | grep robot_control              # 确认进程存活
⑤  ros2 topic echo /diagnose/robot_state --once   # error 字段全 0
⑥  相机（若启用）：systemctl status orbbec_head.service → ros2 topic hz /ob_camera_head/color/image_raw
⑦  底盘：REST 9090 可达 + 已在 IP 白名单 + get_robot_health() 正常 + get_pose() 定位有效
⑧  【必做】确认 /arm/cmd、/head/cmd、/waist/cmd 的 Subscription count ≥ 1
⑨  【必做】音频自检：试播一句，确认音量与链路正常
⑩  【必做】讲稿版本校验：与客户审核版本号一致
⑪  【必做】试跑一次讲解（可关动作干跑），确认脚本与分段无误
⑫  启动 greeting_bringup + greeting_console，确认 /greeting/health 全绿
⑬  主持人确认就绪后，方可进入待机等待领导到达
```

## 9. 实施阶段与里程碑

> 采用 **阶段 + 退出准则（Exit Criteria）** 组织；每阶段必须满足退出准则才进入下一阶段。

| 阶段 | 目标 | 关键交付物 | 退出准则（Exit Criteria） |
| --- | --- | --- | --- |
| **P0 需求冻结与内容准备** | 场景澄清 + 讲稿交付 + 接口索取 | 需求规格、固定范围定义、**客户权威讲稿**、厂商接口申请单 | §13 待确认 Q1/Q2/Q3 有结论；讲稿（含版本号与审核人）已交付 |
| **P1 基线打通** | 搭工作区、打通最小链路 | `greeting_ws` 骨架、`greeting_interfaces` 编译通过、smoke_test | 单命令跑通「播一句 TTS + 做一次鞠躬 + 底盘移位 1 米」 |
| **P2 核心能力** | 各能力包独立可用 | body / voice / nav / console / health 各自可独立验证 | 动作库 ≥6 个礼仪动作通过幅度审查；`/greeting/health` 全绿；控制台单步控制可用 |
| **P3 集成与调优** | 状态机全流程联调 | orchestrator + console + bringup 完整脚本 | 完整接待脚本连续跑通 ≥10 次无人工干预；暂停/续播/回退/跳转全部可用 |
| **P4 现场部署与验收** | 现场建图、标定、礼仪调参、演练 | 地图备份、点位表、讲稿终版、验收报告、SOP 文档 | 通过 §10 验收；**重点场次前完成 ≥3 次完整演练** |

**五个必做的关键动作（全阶段贯穿）**
1. 🔴 **实机复现 `robot_control` 静默退出**：静置 5 分钟，每 30s 检查 `ros2 topic info /arm/cmd` 的 `Subscription count`，量化复现率与恢复耗时（决定 L1 守护策略）。
2. 🔴 **拿到客户权威讲稿**：所有产业规划表述与数据必须逐字确认，**这是本项目的头号交付风险**（R2）。
3. 🔴 **现场建图 + 固定范围边界标定**：确认迎宾位/讲解位/合影位，并实测短距移位精度。
4. 🔴 **礼仪调参**：鞠躬角度、挥手幅度、转头速度需现场与客户/礼仪人员共同确认，不可自行拍板。
5. 🔴 **实机确认算力板型号与显存**（`nvpmodel -q` / `tegrastats`），决定问答环节是否上本地模型。

| # | 用例 | 预期结果 |
| --- | --- | --- |

| A7 | 运行中杀掉 `robot_control` | 守护检出并拉起；期间纯语音讲解不中断 |
| A8 | 按下急停 | 全停；无任何关节动作；控制台提示等待人工 |
| A9 | 讲稿版本号被篡改 | **拒绝启动接待**并告警 |
| A10 | 问答环节提问超范围问题 | 礼貌拒答并引导至工作人员，**不生成臆测内容** |
| A11 | 连续接待 2 场 | 每场正常复位，无状态残留，讲稿版本一致 |
| A12 | 音频链路断开 | 接待前自检拦截；若运行中发生，控制台告警 |

### 10.3 验收标准

- 通过 §1.2 全部 5 条 KPI
- **讲解内容与客户文案 100% 一致**（逐字比对）
- 所有异常场景均有兜底话术或安全停机，**不存在"静默无响应"**
- 主持人全部控制功能（单步/暂停/续播/跳转/接管）实测可用
- 地图、点位表、讲稿终版（含版本号与审核人）、动作库、SOP 均已交付

## 11. 风险登记册

| # | 风险 | 等级 | 影响 | 应对 |
| --- | --- | --- | --- | --- |
| R1 | `robot_control` 静默退出 | 🔴 高 | 接待中断，**领导在场时属现场事故** | `greeting_health` L1/L2 守护 + 自动拉起 + 每次动作前预检 + **接待前全链路自检 SOP** |
| R2 | **讲稿内容出错或口径不符** | 🔴 高 | 政治/商务场合严重失误 | **强制使用客户审核文案**；版本号校验；禁止生成；变更需重新审核 |
| R3 | 本体无 IK，礼仪动作只能示教 | 🔴 高 | 动作开发与现场标定强绑定 | 建立示教流水线；动作库版本化；预留现场礼仪调参时间 |
| R4 | 底盘无软件急停 + 领导在场 | 🔴 高 | 安全风险等级最高 | 物理急停为唯一安全手段；工作人员就近值守；限速 ≤0.4m/s；**原地优先** |
| R5 | 主持人控制台失效 | 🟠 中 | 无法推进/无法接管 | 保留**物理按键**兜底；控制台双端（触屏 + 键盘）；断连告警 |
| R6 | 固定范围边界定义不清 | 🟠 中 | 越界或构图不符 | P0 阶段与客户书面确认范围；软限位 + 物理护栏双重保障 |
| R7 | 音频链路异常（音量小/无声） | 🟠 中 | 讲解听不清，接待失败 | `thor_audio_init.sh` + `amixer`；**接待前强制试播自检** |
| R8 | 算力板型号/显存未确认 | 🟠 中 | 问答环节模型规模无法定 | 实机确认；问答降级为"检索片段播报 + 主持人代答" |
| R9 | 固件 ROS2 消息包未交付 | 🟡 低 | 少 `/go_home` 等便利能力 | 本场景点位少，REST 兜底足够；仍建议索取 |
| R10 | 现场人流/灯光干扰辅助感知 | 🟡 低 | 就位提示不准 | 感知仅为辅助，**不影响主流程**；可整体关闭 |
| R11 | 个人信息合规（影像/人脸） | 🟠 中 | 法律与舆论风险 | **严禁人脸识别与影像留存**；相机可一键关闭；仅本地处理 |
| R12 | DDS 版本升级 segfault | 🟡 低 | 通信中断 | 锁版本，禁止升级；镜像备份 |
